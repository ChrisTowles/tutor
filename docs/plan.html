Tutor: one window for both kids' PCs

Plan, 2026-10-25. Decisions you're most likely to change come first; the build mechanics are at the bottom.

The short version: a Rust GTK4 app on Dad's PC (tutor) and a small Rust agent on each kid's PC (tutor-station). The app starts the agent over SSH and every stream runs through that one SSH connection: screen, webcam, voice, app sound and your mouse/keyboard. Sunshine and Moonlight both go away. Logan's PC and Danielle's PC stay connected at the same time and you switch which one fills the window.

2. Config (data model)

~/.config/tutor/tutor.toml on your PC. The app writes this starter file on first run.

[me]
camera = "/dev/video0"      # C920
mic = "Jabra"               # substring of a PulseAudio source name; "" = default
speakers = ""               # substring of a sink name; "" = default

[[station]]
name = "Logan's PC"
host = "192.168.8.106"      # ssh target, may be user@host
headset = "Jabra"           # their mic + where your voice plays; "" = their defaults
camera = "/dev/video0"

[[station]]
name = "Danielle's PC"
host = "192.168.8.214"
headset = ""
camera = "/dev/video0"
Decision · stations are PCs, not kids Cards are named after the machine ("Logan's PC"), because which kid sits where changes. Rename freely in the file. Toggle state (My cam per PC) lives in memory only — every launch starts from the defaults above.

3. Wire protocol (new types)

Crate tutor-proto, shared by both binaries. Frames on the SSH pipe are a little-endian u32 length then a postcard-encoded message. Audio is raw 48 kHz s16le (mono voice, stereo app sound) like logan-voice.sh today — no codec, the LAN doesn't care.

pub const VERSION: u32 = 1;

pub enum ToStation {
    Hello { version: u32 },
    Streams(Streams),            // sent on connect and on every toggle/switch
    Input(Input),
    DadVoice(Vec<u8>),           // 48k mono s16le, ~20 ms chunks
    DadCam(Vec<u8>),             // one JPEG frame
    Keyframe,                    // decoder lost sync, send an IDR
}

pub struct Streams {
    pub screen_fps: u8,          // 30 selected, 5 background
    pub kid_cam: bool,
    pub kid_voice: bool,
    pub app_audio: bool,
    pub dad_voice: bool,         // play DadVoice on their headset
    pub dad_cam: bool,           // show the overlay
}

pub enum Input {
    Move { x: u16, y: u16 },     // absolute, 0..=65535 across their screen
    Button { button: u8, down: bool },  // 1 left, 2 middle, 3 right, 8/9 side
    Scroll { dx: i32, dy: i32 }, // wheel detents ×120
    Key { code: u16, down: bool },      // Linux evdev keycode (layout-free)
    ReleaseAll,                  // sent when Control turns off
}

pub enum FromStation {
    Hello { version: u32, hostname: String, width: u32, height: u32, encoder: String },
    Video { key: bool, data: Vec<u8> },  // H.264 Annex B access unit
    KidCam(Vec<u8>),                     // JPEG
    KidVoice(Vec<u8>),                   // 48k mono s16le
    AppAudio(Vec<u8>),                   // 48k stereo s16le
    Status(String),                      // "camera busy", "no headset", …
}

A version mismatch in Hello makes the app copy its bundled tutor-station over and reconnect, so updating the agent is just rebuilding on your PC.

4. Architecture choices

Decision · retire Sunshine + Moonlight, write our own agent Keeping Sunshine means writing a GameStream client in Rust: RTSP, an encrypted ENet control channel, Reed-Solomon FEC and pairing — about 15k lines of C in moonlight-common-c. Our own agent is far smaller because COSMIC already offers everything we need to an ordinary process (checked on Logan's PC tonight):
  • Screen: ext_image_copy_capture_v1 — the compositor copies the monitor into our buffer with the cursor drawn in, only when something changed. No KMS, no root, no "Allow remote control?" dialog.
  • Encode: GStreamer nvh264enc (RTX 5060), falling back to openh264enc on a PC without NVIDIA.
  • Mouse/keyboard: a virtual tablet + keyboard through /dev/uinput; Logan's account is already in the input group, which owns it.
  • Your camera on their screen: a wlr-layer-shell overlay surface — replaces the XWayland + xdotool trick.
  • Audio: the same tutor_apps sink trick as logan-audio.sh, so their game sound reaches you without your own voice echoing back.
It also works on Danielle's PC with no Sunshine install. Cost: we own latency tuning. Moonlight is UDP with FEC; we're TCP over SSH. For tutoring (reading their screen, clicking for them) that's fine; it would not be fine for twitch gaming.
Decision · SSH as the only transport ssh -o BatchMode=yes <host> ~/.local/bin/tutor-station, everything multiplexed on stdin/stdout. Auth and encryption are your existing SSH keys; no ports, no pairing, no passwords. Video frames are dropped (and a keyframe requested) when the pipe backs up, so voice never queues behind video.
Decision · hard cutover Once tutor works end to end: delete scripts/logan-cam.sh, dad-cam.sh, logan-audio.sh, logan-voice.sh, the Moonlight AppImage and its pairing, and the Ctrl+Alt+M shortcut; stop and disable Sunshine on Logan's PC (removing the package needs his sudo password — one terminal prompt); rewrite the tutor-time skill to "run tutor". The code lives in a new repo, ~/code/p/tutor (local git only until you say to push it).

6. Build mechanics

Repo layout

tutor/
  Cargo.toml                 # workspace
  crates/proto/              # tutor-proto: messages + framing
  crates/station/            # tutor-station: runs on the kid's PC
    capture.rs   ext-image-copy-capture → appsrc → encoder → Video frames
    media.rs     webcam (v4l2src MJPEG), kid mic (pulsesrc), app audio (tutor_apps.monitor), dad voice (pulsesink)
    overlay.rs   layer-shell surface showing DadCam JPEGs (jpeg decoded in-process)
    input.rs     uinput tablet + keyboard
    audio_route.rs  tutor_apps null sink + loopback on start, undo on exit (pactl)
  crates/app/                # tutor: GTK4 window on Dad's PC
    station.rs   ssh child, reader/writer threads, reconnect loop
    video.rs     appsrc → h264parse → nvh264dec/avdec_h264 → gtk4paintablesink
    audio.rs     kid voice + app audio → pulsesink; my mic → DadVoice
    ui.rs        layout, toggles, cards, input capture
  docs/plan.html, implementation-notes.md
